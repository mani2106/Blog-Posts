## What this repo is

A personal data-science blog by Manimaran Panneerselvam, built on **fastpages** (a Jekyll 4.3 site using the **minima** theme via `remote_theme`). Source lives on `master`; the live site is published to GitHub Pages at https://mani2106.github.io/Blog-Posts/ from a `gh-pages` branch that **CI regenerates on every push to `master`** — never edit `gh-pages` directly.

## Build, preview, deploy

There is no test/lint suite for the blog itself. "Building" means running Jekyll.

**Local preview (Docker — primary path on this Windows machine):**
```powershell
.\tests\blog-dev.ps1 start     # start Jekyll + notebook/word watcher, detached
.\tests\blog-dev.ps1 stop
.\tests\blog-dev.ps1 logs      # tail logs
.\tests\blog-dev.ps1 restart   # restart Jekyll only (fast)
.\tests\blog-dev.ps1 build     # full no-cache rebuild
```
Services come from `docker-compose.yml`; the Jekyll container serves at http://localhost:4000 and a `watcher` container auto-converts `.ipynb`/`.docx` drops. `make server` / `make convert` are the POSIX equivalents via the `Makefile`.

**Local preview (native Ruby):** Ruby 3.3, `bundle install`, then `bundle exec jekyll serve`. Note `Gemfile.lock` is committed but `settings.ini` is gitignored.

**Deploy (automatic):** `.github/workflows/ci.yaml` runs on push to `master` and PRs: checkout → `_action_files` Docker action (converts notebooks + Word docs to `_posts/*.md`) → Ruby 3.3 `bundle exec jekyll build --strict_front_matter` → `peaceiris/actions-gh-pages` publishes `./_site` to `gh-pages`. Strict front matter means a malformed YAML header fails the build.

Other workflows in `.github/workflows/` (`check_config.yaml`, `check_cdns.yaml`, `setup.yaml`, `upgrade.yaml`, `chatops.yaml`, `docker.yaml`, `issue_reminder.yaml`) are stock fastpages automation — rarely touched.

## The two authoring pipelines (most important thing to know)

Both produce files in `_posts/`, but they are **not interchangeable**:

1. **Autogenerated from notebooks/Word docs** — drop a `.ipynb` in `_notebooks/` or `.docx` in `_word/`; the fastpages action converts it to `_posts/YYYY-MM-DD-title.md` on build. These posts carry an `<!-- THIS FILE WAS AUTOGENERATED! DO NOT EDIT! -->` banner, `layout: notebook`, and `nb_path:` in front matter. **Edit the source `.ipynb`/`.docx`, never the generated `.md`** — CI will overwrite the `.md`.
2. **Hand-written Markdown** (recent Azure AI-102, security-hardening, and TOC posts) — authored directly in `_posts/` with `layout: post`. Typical front matter:
   ```yaml
   ---
   title: ...
   layout: post
   summary: "..."
   toc: true
   comments: true
   image: images/<subdir>/<file>.png
   categories: [azure, azure-ai, AI-102]
   ---
   ```
   Notebook-generated front matter instead uses `keywords, description, title, toc, branch, badges, comments, categories, hide, nb_path, layout: notebook`.

Post filenames **must** be `YYYY-MM-DD-title.md` (Jekyll requirement); the date in the filename is what drives ordering/permalinks, e.g. `/azure/azure-ai/ai-102/2025/11/17/...`.

## Critical config facts

- **`baseurl: "/Blog-Posts"`** (`_config.yml`). All internal links/assets must account for it — in Liquid use `{{ '...' | relative_url }}` or `absolute_url`. Hardcoded `/assets/...` paths will 404 in production.
- `url: "https://mani2106.github.io"`, `github_repo: "Blog-Posts"`.
- Feature flags in `_config.yml`: `use_math` (KaTeX), `show_description`, `show_image`, `show_tags`, `google_analytics`, `default_badges` (github/binder/colab for notebook posts).

## Layered customizations (on top of stock fastpages/minima)

These are the areas you'll most often be asked to change:

- **Dark mode** — `assets/js/theme-toggle.js` + an inline FOUC-prevention script in `_includes/custom-head.html` that sets `data-theme` before paint. Persisted in `localStorage` key `theme-preference` (`'light'|'dark'|'auto'`).
- **Sticky/resizable Table of Contents** — `_includes/toc.html` + `assets/js/toc.js` (client-side, parses headings). `toc.html` is injected into `_layouts/post.html` via a `toc-sidebar` aside. Active/recent work area; there is a `toc.html.backup` and a `tests/` folder full of TOC validation scripts (`test-toc-*.ps1`, `toc-*-report.md`).
- **Search** — Lunr-based. `assets/js/search.js` + generated `assets/js/search-data.json`, surfaced by `_pages/search.html`.
- **Comments** — Utterances (`_includes/utterances.html`), gated by `comments: true` per post.
- **Math** — KaTeX auto-render (`_includes/custom-head.html`), gated by `site.use_math`. Delimiters: `$$…$$`, `[%…%]`, `$…$`.
- **SCSS** — `_sass/minima/`: `custom-styles.scss` (your overrides), `custom-variables.scss`, `fastpages-styles.scss`, `fastpages-dracula-highlight.scss`. Dark-mode table colors live here.
- **Admonition includes** — `note, tip, warning, info, important, alert` (Liquid includes in `_includes/`); `{% include note.html content='...' %}` style. Also `image, image-r, video, youtube, twitter` helpers.
- **Custom plugin** — `_plugins/footnote.rb` + `footnote-detail.rb` add Markdown footnote support.

## Image conventions

Post images live under `images/<post-specific-subdir>/`. Notebooks export images to `images/copied_from_nb/` (path set by `doc_path` in `settings.ini`, which is nbdev config). `Thumbs.db` files have been removed and are gitignored.
